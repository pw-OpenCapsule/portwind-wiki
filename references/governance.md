# Governance：5 条治理规则

不靠人审，靠模板和约定。小团队没精力做定期清洁，**约束前置**比事后治理稳。

## 1. 不删，只归档

过时内容打 `[archived YYYY-MM]` 前缀，保留搜索可见性。

为什么不删：被引用的链接断掉比内容过时更糟糕。归档让链接还在，读者看到前缀知道「这是历史信息」。

例子：`[archived 2026-06] [坑] 飞书 docx 推送 >1MB 必超时`（如果未来飞书改了限制就归档）。

## 2. 模板必填段不能跳

每个模板都标了「必填」段。没填完的条目**算未完成**。

强制点：
- `[坑]` 模板第 4 段「下次怎么避免」必填
- design doc 第 5 段「待解决」必填（写「无」也行）
- onboarding 第 4 段「卡住找谁」必须是具体姓名
- 工具雷达必带 `discovered_at` + `review_at`

为什么强制：未完成的条目像未完工的家具，下次接手的人懒得继续填。第一次就填全。

## 3. 外部工具用群体归因

工具雷达条目的来源用：

```
来源：via <群名>，YYYY-MM
```

**不写「@xxx 推荐」**，理由：

- 群体归因降低个人压力（推得不准了不会被追溯）
- 保留分享文化的上下文（「这是在哪个圈子流行的」）
- 比 anonymized 显得更尊重源（说明是哪个群体的智慧）

## 4. 外部工具带 `review_at` 字段

工具雷达每条必带 `discovered_at` + `review_at`（默认 6 月后）。

为什么：外部工具 6-12 个月内可能：

- 项目死了 / 不维护了
- 被更好的替代了
- 跟我们用法不再匹配（我们工作流变了）

季度自清流程：

1. 老员工每季度花 30 分钟扫一遍工具雷达
2. `review_at` 已过的：还用 → 顺手 +6 月；不用 → 加 `[archived]`
3. 链接 404 → 加 `[archived]`
4. 跟自研 Skill 重了 → 合并到对应 Skill 沉淀页 + 本条转「指向 X」

## 5. Cross-link

每个新条目至少 1 个 cross-link 到相关节点：

| 在 X 写新条目时 | 至少链到 |
|---|---|
| Skill 沉淀的工具 | 它依赖的 design doc（架构 & 调研）/ 它撞过的坑（踩坑 & 复盘） |
| 工具雷达 | 关联的自研工具 / 触发的 design doc 调研 |
| 架构 & 调研 design doc | 对应的工具 / 撞坑链接（触发本设计的痛点来源） |
| 踩坑 & 复盘 | 触发的工具 / 后续 fix 进的 design doc |
| 技术分享 | 来源的所有 design doc / 工具 / 坑 |

为什么：wiki 搜索是网状的，越多连接越能找到入口。孤岛条目搜不到 = 等于不存在。

## 不做的治理（明确边界）

- ❌ 不强制审批流（PR-style 流程门槛太高，没人用）
- ❌ 不强制周报 / 月报（人能填的都填了，强制只会有水内容）
- ❌ 不限制谁能写（开放空间是知识沉淀的前提）
- ❌ 不计 KPI / 排名（一写就变质）

## 健康度自查（季度 30 分钟）

```
□ 所有工具雷达条目的 review_at 都看过了
□ [坑] 模板第 4 段都填了
□ design doc 都有 status 字段
□ 6 个月外没复检的 onboarding 都加了 [可能过期] 前缀
□ Homepage 导航表跟实际父节点对得上
□ 链接 404 的都加了 [archived]
```

跑完贴在「踩坑 & 复盘」节点下，作为半年内的「wiki 健康度复盘」记录。
