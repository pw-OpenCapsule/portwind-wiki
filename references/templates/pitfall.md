# Template: [坑] 个人撞过的小坑

> 父节点：**🩹 踩坑 & 复盘** · 标题前缀：`[坑]`（强制）

## 跟 [复盘] 的区别

| | `[坑]` | `[复盘]` |
|---|---|---|
| 严重程度 | 撞了一次自己学到 | 线上事故，影响用户 |
| 长度 | 1 页内 | 严肃复盘文档 |
| 模板 | 本文件 | [postmortem.md](postmortem.md) |
| 更新频次 | 想到就写，门槛低 | P0/P1 事故必写 |

## 标题强制约定

```
[坑] 一句话问题描述（≤ 20 字）
```

例子：
- `[坑] 飞书 docx 推送 >1MB 必超时`
- `[坑] Cloudflare D1 binding 顺序敏感`
- `[坑] wrangler tail 在 personal account 看不到 work account 日志`

第 0 段就是标题，决定别人搜不搜得到。短而有信号。

## 模板（5 段，必填）

```xml
<title>[坑] 一句话问题描述（≤ 20 字）</title>

<h2>1. 现象</h2>
<p>看到的报错 / 异常行为。贴日志片段 / 截图。</p>

<h2>2. 排查路径</h2>
<ul>
  <li>❌ 试过 A，没用 —— ...</li>
  <li>❌ 试过 B，没用 —— ...</li>
  <li>✓ 试 C，命中 —— ...</li>
</ul>

<h2>3. 根因</h2>
<p>真凶。如果是「文档没写」也直说。</p>

<h2>4. 下次怎么避免（必填）</h2>
<p><b>本段必填，否则条目算未完成。</b>具体到：</p>
<ul>
  <li>改某个 lint 规则</li>
  <li>PR 模板加一项</li>
  <li>记住某个 magic number / 配置项</li>
  <li>加进 CLAUDE.md 让 agent 知道</li>
</ul>

<h2>🔗 关联（可选）</h2>
<ul>
  <li>引发这个坑的 commit / PR</li>
  <li>对应工具页：<a href="...">Skill 沉淀 / X</a></li>
  <li>类似的坑：<a href="...">[坑] Y</a></li>
</ul>
```

## 不要的反例

- ❌ 标题：「关于飞书 docx 大小限制的一些思考」（太学术）
- ✅ 标题：「[坑] 飞书 docx 推送 >1MB 必超时」（信号明确）

- ❌ 「以后注意点」（不是 actionable）
- ✅ 「在 push 前算 markdown 字节数，> maxPushBytes 就 fail-fast」（具体）
